# 0003 — state.json transaction seam

Every mutating command hand-rolled the same load-mutate-save envelope around `state.json`. A dropped `save` compiled clean and silently discarded the change; the iteration reset in `end-iteration` mirrored `State::new`'s field list by hand, free to drift. `state.json` is the work loop's memory, so a lost write corrupts it with no error.

**Decision — one closure transaction, `State::update(dir, |&mut State| -> Result<String>)`.** The seam loads before the closure and saves after it, saving only when the closure returns `Ok`; a closure `Err` leaves the file untouched. The dropped-save failure mode becomes unrepresentable — the seam saves, not the caller — and a failed mutation rolls back for free (it was only ever in memory). All nine mutating commands route through it. *Rejected:* a generic `Result<T>` return — every caller returns the command's message string, so `<T>` is an abstraction no caller needs. *Rejected:* an RAII guard that saves on drop — drop can't return an error, so a failing save would panic or be swallowed.

**Decision — `state.json`-only scope; no cross-file atomicity.** `update` owns `state.json` and nothing else. `end-iteration` also writes the PRD `.md`; that write stays a side effect *inside* the closure, preserving today's PRD-first, non-atomic ordering. *Trade-off:* a crash between the PRD write and the `state.json` save can leave the two disagreeing. Accepted because each file is already individually torn-proof (atomic temp-then-rename) and a two-file commit protocol is a large mechanism for a failure window that has never bitten a single-user CLI. Revisit if the loop ever runs concurrently.

**Decision — bounded scope; fields stay `pub`, no god-struct privatization.** The seam owns the transaction, not the schema — the non-`Registry` `State` fields remain publicly writable, mutated directly inside each closure. *Trade-off:* "no command calls `state::save` directly" is enforced by convention plus a whole-crate grep, not by the type system — `state::save` stays `pub` because `init` needs it, so a future command could bypass the seam and still compile. Accepted to ship the transaction without a large encapsulation pass mixed in; full privatization is a separate candidate. Re-run the grep when adding a mutating command.
